Die IdeeThe idea

Die Fotos im MittelpunktThe photos at the centre

Eine Fotowebsite mit WordPress bringt viel mit, was man nicht braucht: Plugins, Updates, Datenbank, Angriffsfläche. Lichtkammer macht nur das Nötige. Fotos hochladen, in Galerien ordnen, Seiten schreiben und auf „Veröffentlichen“ klicken. Dann erzeugt Lichtkammer die öffentliche Website als fertige HTML-Dateien. Besucher bekommen schnelle, ruhige Seiten, und auf dem Server läuft beim Ansehen kein Programm.A photo website on WordPress brings a lot you don’t need: plugins, updates, a database, attack surface. Lichtkammer only does what is necessary. Upload photos, arrange them in galleries, write pages and click “Publish”. Lichtkammer then generates the public website as ready-made HTML files. Visitors get fast, calm pages, and no program runs on the server while they look around.

Was Lichtkammer kannWhat Lichtkammer does

Einfach für alle, die Fotos pflegenSimple for everyone who looks after photos

BilderImages

Originale bleiben unberührtOriginals stay untouched

Hochladen in Stücken mit Fortschrittsanzeige, auch bei großen Dateien und knappen Server-Grenzen. Jedes Foto wird einzeln verarbeitet: Varianten in mehreren Größen als AVIF, WebP und JPEG. GPS-Daten werden aus allem Öffentlichen entfernt, die Originale nie überschrieben.Chunked uploads with a progress bar, even for large files and tight server limits. Every photo is processed on its own: variants in several sizes as AVIF, WebP and JPEG. GPS data is removed from everything public, originals are never overwritten.

GalerienGalleries

Ruhig präsentiertCalmly presented

Galerien als Kacheln, gleich hohe Bildreihen und eine Lightbox mit Tastatur, Wischgesten und Bildinfo. Fotografen haben eigene Seiten. Zu jedem Foto gehört ein Alt-Text (Pflicht), damit die Seite für alle lesbar bleibt. Ein Papierkorb und Mehrfachbearbeitung erleichtern die Pflege.Galleries as tiles, rows of equal height and a lightbox with keyboard, swipe gestures and image info. Photographers have their own pages. Every photo needs alt text (required) so the site stays readable for everyone. A trash bin and bulk editing make upkeep easier.

SeitenPages

Mit Blöcken gestaltenBuilt from blocks

Seiten wie „Über uns“ oder Ausstellungen entstehen aus Blöcken: Text, Foto, Raster, Zitat, Knopf, Spalten, Bild und Text, Karussell und Titelbild. Auch die Startseite besteht aus Blöcken. Den Bildausschnitt bestimmst du selbst. Logos, Menü und Fußzeile pflegst du im Admin.Pages such as “About us” or exhibitions are built from blocks: text, photo, grid, quote, button, columns, image and text, carousel and cover image. The home page is built from blocks too. You choose the image crop yourself. Logos, menu and footer are managed in the admin.

VeröffentlichenPublishing

Erst Vorschau, dann livePreview first, then live

Änderungen sind erst nach „Veröffentlichen“ sichtbar. Vorher zeigt die Vorschau die Seite genau so, wie Besucher sie sehen werden. Was noch im Entwurf steckt, nennt Lichtkammer beim Namen. Ist etwas schiefgegangen, nimmt „Rückgängig“ die Veröffentlichung zurück.Changes only become visible after “Publish”. Before that, the preview shows the page exactly as visitors will see it. Lichtkammer names whatever is still in draft. If something went wrong, “Undo” takes the publication back.

Aktualisieren und WiederherstellenUpdating and restoring

Aktualisieren: Auf dem Webspace das neue Zip über die alte Installation hochladen (.env, Daten und Fotos sind nicht im Zip, die Datenbank aktualisiert sich selbst). In Docker das neue Zip über denselben Ordner entpacken und noch einmal docker compose up -d --build. Vorher eine Sicherung ziehen. Wiederherstellen (neuer Server nach einem Totalverlust): dieselbe Version installieren, die .env mit dem alten LK_APP_KEY anlegen, die Sicherung bereitstellen und unter /admin/setup „Stattdessen eine Sicherung einspielen“ wählen; die Schritte stehen in der PDF-Anleitung, Kapitel 4.Updating: on web hosting, upload the new zip over the old installation (.env, data and photos are not in the zip; the database updates itself). With Docker, unpack the new zip over the same folder and run docker compose up -d --build again. Take a backup first. Restoring (a new server after total loss): install the same version, create the .env with the old LK_APP_KEY, put the backup in place and choose “restore a backup instead” at /admin/setup; the steps are in the PDF manual, chapter 4.

EchtheitAuthenticity

Ist das Paket wirklich von luro?Is the package really from luro?

Du lädst ein Programm aus dem Internet und spielst es auf deinen Server. Deshalb kannst du prüfen, dass die Datei unverändert und von mir ist. Es gibt zwei Wege, der erste ist schnell, der zweite ist der stärkere.You download a program from the internet and put it on your server. So you can check that the file is unchanged and from me. There are two ways: the first is quick, the second is the stronger one.

Weg 1: Prüfsumme (SHA-256) vergleichenWay 1: compare the checksum (SHA-256)

Die Prüfsumme ist ein Fingerabdruck der Datei: Ändert sich auch nur ein Zeichen, kommt etwas ganz anderes heraus. Rechne ihn auf deinem Rechner aus und vergleiche ihn mit dem Wert, der hier auf der Seite (HTTPS, Domain lurohome.de) steht:The checksum is a fingerprint of the file: change a single character and something completely different comes out. Calculate it on your computer and compare it with the value shown here on this page (HTTPS, domain lurohome.de):

# Mac
shasum -a 256 @@LK_ZIP@@
# Linux
sha256sum @@LK_ZIP@@
# Windows (PowerShell)
Get-FileHash .\@@LK_ZIP@@ -Algorithm SHA256

Soll-Wert:Expected value: @@LK_SHA@@

Stimmen beide überein, ist die Datei beim Laden nicht beschädigt oder verändert worden. Das schützt vor Übertragungsfehlern, aber nicht davor, dass jemand Datei und Seite austauscht. Dafür gibt es Weg 2.If they match, the file was not damaged or changed while downloading. That guards against transfer errors, but not against someone replacing the file and this page. Way 2 covers that.

Weg 2: Signatur prüfen (ssh-keygen)Way 2: verify the signature (ssh-keygen)

Ich habe das Zip mit meinem Schlüssel signiert. Dafür brauchst du nur ssh-keygen (auf Mac, Linux und Windows 10/11 dabei). Lege diese drei Dateien in einen Ordner und öffne dort ein Terminal: das Zip, die Signatur @@LK_ZIP@@.sig und die Liste meiner Schlüssel allowed_signers.I signed the zip with my key. All you need is ssh-keygen (included on Mac, Linux and Windows 10/11). Put these three files in one folder and open a terminal there: the zip, the signature @@LK_ZIP@@.sig and the list of my keys allowed_signers.

# Mac / Linux
ssh-keygen -Y verify -f allowed_signers -I @@SIG_ID@@ -n lichtkammer \
  -s @@LK_ZIP@@.sig < @@LK_ZIP@@

# Windows (PowerShell)
cmd /c "ssh-keygen -Y verify -f allowed_signers -I @@SIG_ID@@ -n lichtkammer -s @@LK_ZIP@@.sig < @@LK_ZIP@@"

Erwartet wird eine Zeile, die mit Good "lichtkammer" signature for @@SIG_ID@@ beginnt. Jede andere Meldung (zum Beispiel „Could not verify signature“) heißt: Nicht benutzen und mir schreiben. Dieselbe Prüfung bündelt das Skript tools/pruefen-signatur.sh aus dem Quellcode.You should see a line starting with Good "lichtkammer" signature for @@SIG_ID@@. Any other message (for example “Could not verify signature”) means: do not use it, and write to me. The script tools/pruefen-signatur.sh in the source code does the same check.

Wichtig: allowed_signers kommt von derselben Seite wie das Paket. Der Schlüssel schützt also dort am besten, wo du ihn dir einmal über einen zweiten Weg bestätigen lässt (frag mich nach dem Fingerabdruck) und die Datei danach aufbewahrst.Important: allowed_signers comes from the same site as the package. The key protects best if you confirm it once through a second channel (ask me for the fingerprint) and then keep the file.

Noch nicht aktiv. Die Signatur kommt mit dem nächsten Testpaket. Dann liegen hier die Datei .sig und die Schlüsselliste allowed_signers, und an dieser Stelle steht die Prüfung Schritt für Schritt (Mac, Linux, Windows). Bis dahin gilt Weg 1.Not active yet. The signature will come with the next test package. Then the .sig file and the key list allowed_signers will be here, with the check step by step (Mac, Linux, Windows). Until then, use way 1.
